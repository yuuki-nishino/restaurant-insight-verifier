# ADR-0001: Jev APIが使えない場合はモック関数で代替する

日付: 2026-09-24
ステータス: 承認

## コンテキスト

本アプリの核はJev APIによる口コミ分類（分類フェーズ）とインサイト文の事実検証（検証フェーズ）である。しかしJevはアーリーアクセス段階であり、MVP実装のタイミングで一般公開APIが利用できない可能性がある。

## 決定

Jev APIと同一の入出力スキーマ（[api-spec.md](../api-spec.md)参照）を持つモック関数（ルールベースの簡易分類・簡易検証）を用意し、Jevが利用できない間はこれで代替する。

## 理由

- MVPの目的は「1日で通し動作するデモを作る」ことであり、外部APIのアーリーアクセス承認待ちでブロックされるべきではない。
- 入出力スキーマを揃えておけば、本物のJev APIが使えるようになった時点で呼び出し部分だけ差し替えれば良く、他のレイヤー（DB保存・集計・表示）に影響しない。

## 影響

- 分類・検証ロジックの呼び出し口は抽象化しておく（例: `classifyReview()` / `verifyClaim()` のような関数インターフェースを用意し、内部実装をJev API呼び出しかモック関数かで切り替えられるようにする）。
- モック関数はキーワードベースの簡易判定でよく、精度は求めない（動作確認が目的）。
- Jevアーリーアクセスが使えるようになったら、このADRのステータスを更新し、切り替え作業をIssue化する。
